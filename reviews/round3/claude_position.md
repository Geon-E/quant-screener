## Q1. EBITDA/EV → **B (EBIT/EV로 교체)** · 확신도 중

**근거**
- 계산 가능 비율이 12%인 지표는 가치 묶음에서 사실상 빠진 것과 같다.
- 계산되는 3개사가 "감가상각비를 표준 계정으로 공시하는 회사"라는 공시 관행으로 걸러진 집단이라 편향도 생긴다.
- EBIT/EV는 같은 개념("기업가치 대비 영업이익")이고 96%가 계산된다.
- D(혼합)는 회사마다 다른 지표를 같은 백분위에 섞어서 비교 가능성을 해친다.

**인정하는 단점**
- 감가상각이 큰 장치산업이 EBIT/EV에서 불리하다.
- 다만 업종 내 비교(D-03)라서 같은 장치산업끼리 비교하므로 영향이 줄어든다.

**반증 조건**
- 전 종목 확대 후 C 방식의 감가상각비 커버리지가 70% 이상으로 확인되면, EBITDA/EV 복귀를 다시 검토한다 (결과를 보기 전에 판단).

## Q3. 1단계의 약점

### 남은 중대한 약점

1. **원천값 매핑의 사람 확인이 안 됐다.**
   - 엑셀 독립 재계산은 "계산 로직"만 검증한다.
   - 엑셀이 받는 입력(원천값) 자체가 파이썬 매핑 결과라서, 매핑 오류는 그대로 통과한다.
2. **대체 규칙 3종의 위험**
   - `no_nci`: 연결인데 비지배지분 행이 없으면 전체 = 지배주주로 본다. 비지배지분이 있는데 계정명이 특이해서 못 찾은 경우에도 잘못 적용될 수 있다.
   - 서수 규칙: 손익계산서 행 순서에 의존한다.
   - 금융원가 대용: 외환손실 등이 섞여 이자보상배율이 과소 계산된다. 대용 사용 여부는 플래그로 남기지만, 점수에는 그대로 반영된다.
3. **표본이 작고 편향돼 있다.**
   - 표본 28개사 중 적자·소형·정정 기업이 의도적으로 많아서, 커버리지 수치(예: CFO/NI 56%)가 전체 시장 대비 낮게 나온다.
   - 전 종목에서 다시 측정해야 한다.
4. **시점 정합성은 플래그만 있다.**
   - 최초본 XBRL은 받아두기만 했고 파싱하지 않았다.
   - 기준일이 오늘이라 아직 문제가 드러나지 않았을 뿐이고, 과거 시점 평가에서는 정정 전 값이 필요하다.
5. **12월 외 결산 기업이 통째로 빠진다.**
   - 비율은 작지만(표본 후보 기준 약 1~2%), 빠진 사실을 유니버스 제외 사유로 기록해야 한다.

### 2단계 전에 반드시 고칠 것

1. 원천값 확인 통과 (Q4)
2. Q6 규칙 수정
3. `no_nci` 적용 조건 강화: 비지배지분 계정이 없을 뿐 아니라 "지배기업"이라는 명칭이 붙은 행도 전혀 없을 때만 적용
4. 호출량을 반영한 전 종목 적재 계획 (회사당 약 55회 × 2,500개사 ≈ 14만 회 → 일 한도로 7일 이상) + 재개 실측
5. 대체 규칙이 적용된 종목 비율을 커버리지 보고서에 표시

### 이자비용 대체 규칙에 대한 별도 의견
- 금융원가 대용은 **이자보상배율에만** 쓰고, 대용이면 "신뢰도 낮음" 표시와 함께 점수 비교에서 별도 처리하는 편이 낫다.
- 표본에서는 25개사 중 2개사만 해당했다.

## Q4. 원천값 확인 → **D (층화 약 100행을 사용자·GPT 분담)** · 확신도 중

**근거**
- 700행 전수 확인(A)은 부담이 커서 실제로 끝나지 않을 위험이 있다.
- GPT 단독(C)은 DART 원문 접근이 불안정할 수 있다.
- 핵심 항목을 회사별로 고르게 뽑으면, 매핑 규칙별 오류를 효율적으로 잡을 수 있다.

**표본 구성 (제안)**
- 회사마다: 지배주주순이익(당기), 지배주주자본(당기말), 영업이익(당기), 이자부부채(당기말)
- 25개사 × 4행 = 100행
- 대체 규칙(`separate_only`·`no_nci`·`ordinal`·`pattern`)이 적용된 행은 전부 포함

**통과 기준**
- 표준 계정 ID로 매핑된 행: 오류 0건
- 오류가 1건이라도 나오면 같은 규칙이 적용된 행을 전수 확인한다.
- 대체 규칙 행: 오류율 5% 이하. 초과하면 그 규칙을 폐지하거나 무효 처리로 전환한다.

**반증 조건**
- 사용자·GPT 판정이 서로 다른 행이 10%를 넘으면 → 확인 절차(무엇을 비교하는지) 자체를 다시 정의한다.

## Q5. 우선순위 → **a → b → d·e → c → f** · 확신도 중

| 순서 | 작업 | 이유 |
|---|---|---|
| 1 | a 일일 운영 | 완료 기준 5·10과 D-08이 걸려 있다. 매일 쌓이는 실전 추적 데이터는 늦게 시작할수록 손해다 |
| 2 | b 수정주가 | 모멘텀과 모든 백테스트 수익률의 전제. 이게 없으면 2단계 백테스트를 시작할 수 없다 |
| 3 | d·e 관리종목·상장폐지 | 유니버스 정확성. 표본 실험이라 작업량이 작다 |
| 4 | c XBRL 파싱 | 백테스트 시점 정합성에 필요하다. 다만 실전 추적에는 당장 필요 없고, 백테스트 직전까지만 하면 된다 |
| 5 | f 전 종목 확대 | 위 항목과 원천값 확인(Q4)을 통과한 규칙으로 확대해야 오류가 대규모로 퍼지지 않는다 |

**반증 조건**
- 수정주가 작업이 공시 파싱 문제로 길어지면 → f를 먼저 진행하고, 시세 기반 지표만으로 전 종목 수집을 병행한다.

## Q6. 계정 못 찾으면 0 → **B** · 확신도 상

**근거**
- 무차입 기업(진짜 0)과 매핑 실패(모름)는 다르다. 둘을 같은 0으로 처리하면 GPT 1차 지적(무효 ≠ 0)에 어긋난다.
- 재무상태표에 관련 명칭이 하나도 없다는 것은 무차입의 합리적 근거다.
- 명칭이 있는데 못 찾았다면 "모름"이므로 무효가 맞다.
- C는 실제 무차입 기업까지 무효로 만들어 EV 커버리지를 불필요하게 낮춘다.

**반증 조건**
- B를 적용했을 때 무효가 되는 종목이 많고(예: 10% 이상), 원천 확인 결과 그 대부분이 실제 무차입이면 → 명칭 패턴을 보완한다.
