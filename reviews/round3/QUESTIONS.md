## Q1. EBITDA/EV 지표 처리 (D-20)

1단계 표본 25개사 중 EBITDA/EV 계산 가능 3개사(12%). 같은 표본에서 EBIT/EV(영업이익/EV)는 24개사(96%).

| 선택안 | 내용 |
|---|---|
| A | EBITDA/EV 유지 (계산 가능할 때만, 나머지는 무효) |
| B | EBIT/EV로 교체 |
| C | 감가상각비를 비표준 계정명·주석까지 확장 수집 후 EBITDA/EV 유지 |
| D | 회사별로 EBITDA/EV가 있으면 그것, 없으면 EBIT/EV 사용 (혼합) |

## Q3. 1단계 구현·검증 방식의 약점

코드와 산출물을 보고 다음을 각각 최대 5개씩 제시한다.
- 아직 남은 중대한 약점
- 2단계(DART 전 종목 확대) 전에 반드시 고쳐야 할 것

특히 검토할 부분:
- 계정 규칙의 대체 규칙: `separate_only`, `no_nci`, 지배주주 서수 규칙
- 이자비용을 이자지급(CF) → 금융원가로 대체하는 규칙
- 엑셀 독립 재계산의 독립성 수준

## Q4. 원천값(계정 매핑) 사람 확인 방법

워크북 '원천값 확인' 시트는 700행이다.

| 선택안 | 내용 |
|---|---|
| A | 사용자가 700행 전부 확인 |
| B | 층화 추출 (회사별 핵심 항목 — 지배주주순이익·지배주주자본·영업이익·이자부부채 등 약 100행) 확인. 오류가 나오면 해당 항목 전수 확인 |
| C | GPT가 DART 원문 링크로 확인 |
| D | B의 표본을 사용자와 GPT가 나눠 확인 |

추가로, **"통과" 기준**(허용 오류 수·비율)을 제시한다.

## Q6. 계정을 못 찾았을 때 0으로 보는 규칙

현재 이자부부채·장기부채·단기금융상품은 해당 계정이 없으면 0으로 본다 (`zero_default`). 무차입 기업을 위한 규칙이다. 그러나 비표준 계정만 쓰는 회사에서 차입금이 있는데 못 찾으면 EV가 과소 계산된다.

| 선택안 | 내용 |
|---|---|
| A | 현행 유지 (없으면 0) |
| B | 재무상태표에 차입금·사채·리스부채 계열 명칭이 **하나도 없을 때만** 0, 명칭은 있는데 매핑 실패면 무효 |
| C | 못 찾으면 항상 무효 |
