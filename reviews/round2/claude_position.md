## Q1. v0.2와 0단계 결과의 약점

### 남아 있는 중대한 약점

1. **최초 적재 호출량 과소평가**
   - 상장사 약 2,700개 × 2015~2026 약 46개 보고서 × (연결 없으면 별도 재조회)로 계산하면 10만 건을 넘는다.
   - 가이드상 일 2만 건 기준이면 최소 6~7일이 걸린다. XBRL 최초본까지 더하면 더 늘어난다.
   - 설계의 "며칠 분할"은 너무 낙관적이다. **중단 후 이어받기(체크포인트)** 와 진행률 기록이 필수다.
2. **GitHub Actions 실행 환경 제약**
   - 작업당 실행 시간 제한이 있고, 러너는 실행이 끝나면 초기화된다.
   - 장기 적재는 매일 이어서 실행하는 구조로 설계해야 한다.
3. **감가상각비 매핑 위험**
   - EBITDA의 감가상각비는 현금흐름표 조정 항목에서 가져와야 하는데, 기업마다 표현이 제각각이다.
   - EBITDA/EV 지표의 데이터 충족률이 낮아질 위험이 있다.
4. **PBR–ROE 잔차의 실효성**
   - 적용 조건(사업군 유효 표본 15개 이상, R² 0.1 이상)이 엄격하다.
   - 실제로 많은 사업군에서 비활성화되어, 가치 묶음이 사실상 3개 지표로 줄어들 수 있다.
5. **과거 업종 분류 미확보**
   - `induty_code`는 현재 값만 제공된다.
   - 과거 백테스트에 현재 분류를 쓰면 일종의 미래 정보가 섞인다 (업종을 바꾼 기업).

### 실측 결과로 바뀌어야 하는 설계 요소

1. **백테스트 실질 시작 시점**
   - 재무가 2015 사업연도부터라 TTM 4개 분기를 처음 확보하는 건 2015년 사업보고서 공시 이후다 (2016년 3~4월).
   - 따라서 개발 구간은 "2015~2021"이 아니라 **2016년 2분기~2021년**이 맞다.
2. **계정 매핑 1순위 = 표준 계정 ID**
   - 0단계에서 `ifrs-full_...` 형태의 표준 계정 ID가 확인됐다.
   - 계정명 패턴 매칭은 보조로 내린다.
3. **시점 정합성 구현 경로 확정**
   - 재무 API = 최신본, XBRL = 최초본 (DESIGN 4.1에 반영 완료).
4. **리밸런싱 규칙 유지**
   - "기한 + 5영업일" 시점에 약 97% 반영된다는 실측으로 근거가 생겼다.

## Q2. 비교 사업군 구성 → **B** (확신도 중)

**근거**
- A(실행 중 자동 병합)는 시점마다 비교 집단이 달라져 재현성이 깨진다.
- C는 소표본 문제를 방치한다.
- D(축소추정)는 이론적으로 가장 좋지만 구현·설명이 복잡하다. 첫 버전에 넣기보다 실험 후보로 둔다.
- B는 단순하고 버전으로 관리할 수 있으며, 사람의 업종 판단을 반영할 수 있다.

**반증 조건**
- 신뢰도 "낮음" 종목의 비중이 20%를 넘는 경우
- 소표본 사업군 종목의 성과가 체계적으로 다르게 나오는 경우
- → 이때는 D로 전환을 검토한다.

## Q3. 계산 검증과 백테스트 순서 → **A** (확신도 상)

**근거**
- 계산이 틀린 엔진으로 돌린 백테스트는 틀린 결론에 신뢰를 부여해서 해롭다.
- 계산 검증(표본 20~30개사)은 며칠이면 끝나는 작업이라, 백테스트가 늦어지는 비용이 작다.

**반증 조건**
- 계산 검증이 예상보다 길어져(예: 4주 이상) 전략 자체의 유효성 판단이 지나치게 늦어지는 경우
- → 이때는 C(소표본 탐색)를 허용한다.

## Q6. XBRL 최초본 적용 범위 → **A** (확신도 중)

**근거**
- B는 XBRL 파싱을 전 공시에 적용해 1단계 작업량을 크게 늘린다.
- 재무 API와 XBRL의 값이 같은지 대조하는 일도 결국 필요하다.
- C는 GPT 1차 지적(시점 정합성)을 약화한다.
- A는 영향받는 건(정정 공시)만 정확히 처리한다.

**반증 조건**
- 정정공시 비율이 예상보다 높은 경우 (예: 상장사의 15% 이상)
- 최신본과 최초본의 값 차이가 점수 순위에 미치는 영향이 큰 경우
- → 이때는 B로 전환한다.

## Q7. 코스피 관리종목 → **B** (확신도 하~중)

**근거**
- 공식 API이고 지정·해제 이력을 날짜별로 얻을 수 있어 백테스트에도 쓸 수 있다.
- A는 페이지 구조 변경에 취약하다.

**불확실성**
- 관리종목 지정은 거래소 공시이므로, DART 공시 검색에서 일관되게 잡히는지 확인이 필요하다.
- 확인 결과 누락이 있으면 A를 보조로 쓴다.

**반증 조건**
- 알려진 관리종목 표본을 DART 검색으로 재현하지 못하는 경우

## Q8. 수정주가 → **D** (확신도 중)

## Q9. 1단계 착수 범위 → **C** (확신도 상)

**근거**
- 시세(KRX)는 하루 두 번의 호출로 전 종목을 받을 수 있다. 표본으로 제한할 이유가 없다.
- 재무(DART)는 호출량·매핑 위험이 크다. 표본으로 전 과정을 먼저 검증한 뒤 확대해야 한다.
- 결과적으로 A의 장점(표본으로 끝까지 검증)과 시세 전 종목 확보를 함께 얻는다.

**1단계 완료 기준에 추가할 항목**
- **결정성**: 같은 L0 입력으로 두 번 실행하면 L1·L2 결과의 해시가 일치한다.
- **보안**: 결과물·로그에 키 문자열이 없는지 자동 검사한다.
- **호출량 리포트**: 실행마다 API별 호출 수와 남은 한도 추정치를 기록한다.
- **재개 가능성**: 적재를 중간에 끊었다가 다시 실행해도 중복·누락이 없다.

## Q10. 상장폐지 이력 소스 → **B** (확신도 중)

**근거**
- 수익률 계산에 실제로 필요한 것은 "마지막으로 거래된 날짜와 가격"이다. KRX 공식 시세에서 직접 얻을 수 있다.
- 폐지 사유(합병 등 손실이 아닌 폐지와 부실 폐지의 구분)는 비공식 목록에서 보완한다.
- 공식 데이터를 주로 써야 재현성이 높다.

**주의**
- 마지막 거래일과 공식 폐지일은 다를 수 있다 (거래정지 후 폐지). 둘을 구분해 저장한다.

**반증 조건**
- 시세 공백(거래정지)과 폐지를 구분하지 못해 오분류가 생기는 경우
