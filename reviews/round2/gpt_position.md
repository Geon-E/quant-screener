## Q1. 설계 v0.2와 0단계 실측 결과의 약점

### 아직 남아 있는 중대한 약점 — 최대 5개

1. **과거 시점 재현은 아직 완성되지 않았다.** 최초 공시 XBRL을 확보할 수 있다는 사실과, 전체 백테스트 기간에 대해 공시별 최초본·정정본을 빠짐없이 재구성할 수 있다는 것은 다르다. XBRL 파싱, 정정 대상 연결, 계정 표준화, 예외 기업 처리까지 검증해야 한다.
2. **수정주가와 기업행위 처리는 수익률 검증의 핵심 미해결 항목이다.** 분할·병합·유상증자·무상증자·감자 등을 잘못 처리하면 모멘텀과 포트폴리오 수익률 모두 왜곡될 수 있다.
3. **상장폐지 종목의 가격 이력 확보가 완전한 청산 수익률을 보장하지 않는다.** 마지막 거래일, 정리매매 가격, 거래정지, 합병 대가 및 실제 회수액은 서로 다른 문제다.
4. **리밸런싱의 일률적인 ‘법정기한+5영업일’ 규칙은 최신 정보 반영률을 높이지만, 기업별 공시 시점·제출기한 예외·공시 지연을 제대로 반영하는지 추가 검증이 필요하다.** 보고서 기한과 실제 데이터 이용 가능 시각을 동일시하면 안 된다.
5. **점수 체계의 예측력이 아직 입증되지 않았다.** 고정 가중치, 업종 상대 백분위, F-스코어 및 위험 필터가 실제 비용 차감 후 성과에 기여하는지, 또는 특정 업종·기간·소형주 노출만 반영하는지 알 수 없다.

### 실측 결과로 인해 바뀌어야 하는 설계 요소 — 최대 5개

1. **원본 데이터와 점수 이력의 보관·재현 규칙을 구현 명세로 확정해야 한다.** 실측으로 원본을 확보할 수 있다는 것이 확인된 만큼, 원본 응답·수집 시각·해시·공시 접수번호·정규화 버전·전략 버전을 실제로 연결해야 한다.
2. **최초본 XBRL과 최신 정정본을 서로 다른 데이터 관점으로 명확히 분리해야 한다.** 재무 API가 최신 정정본을 반환한다는 실측 결과를 고려하면, API 응답을 과거 시점의 최초 공시값으로 취급해서는 안 된다.
3. **코스피 관리종목 필터는 구현 전까지 ‘완료된 필터’로 간주하지 않아야 한다.** 현재 확인된 KRX 종목기본정보만으로는 코스피 식별에 공백이 있다.
4. **수정주가 보정은 단순 가격 급변 탐지로 끝내지 말고 기업행위 근거와 대조하는 절차를 가져야 한다.** 공식 데이터만으로 가능한 범위와 외부 소스가 필요한 범위를 구분한다.
5. **‘최초 적재가 가능하다’는 판정을 ‘전체 과거 데이터가 완전하다’는 판정과 분리해야 한다.** 재무·가격·상장폐지·기업행위별 커버리지와 결측률을 각각 측정하고, 백테스트 가능한 시작일은 가장 취약한 필수 데이터의 범위에 맞춰 정해야 한다.

## Q2. 비교 사업군 구성 방식

- **선택: B — 사람이 검토한 고정 사업군 표를 버전 관리하고, 소표본은 낮은 신뢰도로 표시한다.**
- **근거:** 실행할 때마다 표본 수 기준으로 자동 병합하면 시장 상황에 따라 비교집단과 점수가 달라져 시점 간 재현성이 약해진다. KSIC 원분류만 사용하는 C는 동일 KSIC 내 사업모델 차이를 해결하지 못한다. B는 분류 근거와 적용일을 기록하고 과거 버전을 재현할 수 있다.
- **보완:** 고정 사업군은 사람이 임의로 수익이 잘 나도록 묶지 않도록 분류 기준·예외 사유·검토일을 기록한다. 표본 수가 작을 때는 단순히 ‘낮은 신뢰도’만 표시하지 말고, 점수를 숨기거나 전체 시장 점수와 혼합하는 대안도 검증한다.
- **반증 조건:** B의 사업군 표가 반복적인 수작업을 요구하고 분류자 간 일치도가 낮거나, B가 KSIC 원분류·표본 크기 보정 방식보다 일관되게 낮은 표본 외 성과를 보일 경우 재검토한다.
- **확신도: 상**

## Q3. 계산 검증과 백테스트의 순서

- **선택: C — 소수 표본의 탐색적 백테스트와 계산 검증을 병행하고, 검증 완료 후 정식 백테스트를 수행한다.**
- **근거:** A는 계산 오류를 줄이는 데 유리하지만 과거 데이터의 실제 확보 가능성, 기업행위 보정 및 거래 가정의 문제를 너무 늦게 발견할 수 있다. B처럼 검증 전 결과를 정식 성과로 취급하는 것도 위험하다. C는 탐색 결과를 성과 증거로 과장하지 않는다는 조건에서 가장 효율적이다.
- **보완:** 탐색적 백테스트 결과로 공식·가중치·필터를 계속 조정하면 과최적화 위험이 커진다. 탐색용 구간과 최종 검증 구간을 분리하고, 정식 결과는 계정 매핑 및 수익률 계산 테스트 통과 후에만 공개한다.
- **반증 조건:** 탐색적 파이프라인이 계산 검증에 필요한 코드를 중복시키거나, 초기 결과가 검증되지 않은 공식을 고착시키는 문제가 발생하면 A에 가까운 순차 방식으로 변경한다.
- **확신도: 중**

## Q4. 점수 이력 저장

## Q5. L0~L2 데이터 보관 위치

- **선택: A — GitHub Release 자산으로 시작하되, 크기·보존·복구 한계를 측정하고 저장소 교체 인터페이스를 둔다.**

- **보완:** Release 자산을 무제한·영구 보관으로 가정하지 않는다. 파일 크기, 다운로드·업로드 실패, 보존 정책, 백업 복구를 실측하고, L0 원본은 해시와 매니페스트로 검증한다.
- **반증 조건:** 데이터 용량이나 다운로드·업로드 한계, 보존 요구가 Release 자산의 실측 한계를 넘으면 C(객체 저장소)로 이전한다.
- **확신도: 중**

## Q6. 최초 공시 값 복원(XBRL) 적용 범위

- **선택: A — 1단계에서는 정정공시가 있는 기업의 최초본을 우선 확보하고, 백테스트 범위 확대 시 필요한 기간으로 넓힌다.**
- **근거:** 0단계에서 XBRL 원본 확보 가능성은 확인됐지만, 전 공시의 XBRL 파싱·계정 매핑을 처음부터 적용하는 B의 비용과 실패율은 아직 측정되지 않았다. C는 과거 백테스트에 최신 정정본을 쓰게 되어 시점 정합성 검증의 핵심을 포기한다.
- **보완:** ‘정정공시가 있는 기업만’으로 시작하더라도, 어떤 기업·기간에 최초본 복원이 완료됐는지 기록해야 한다. 복원 실패를 최신본으로 조용히 대체하지 말고, 시점 정합성 미충족 플래그와 백테스트 포함 여부를 명시한다.
- **반증 조건:** 정정공시 여부를 신뢰성 있게 식별할 수 없거나 선택적 복원으로 인한 표본 편향이 크고, 전체 XBRL 수집이 실측상 충분히 안정적·저비용이면 B로 전환한다.
- **확신도: 중**

## Q7. 코스피 관리종목 식별

- **선택: A — KIND 관리종목 현황을 우선 조사·수집하고, DART 공시는 이력 및 교차검증에 활용한다.**

- **반증 조건:** KIND 페이지의 자동 수집이 지속적으로 깨지거나 과거 이력을 확보하지 못하고, DART 방식이 더 완전하고 재현 가능한 이력을 제공하면 B를 주 소스로 바꾼다.
- **확신도: 중**

## Q8. 수정주가 계산

- **선택: D — 공식 기업행위 공시로 보정하고, 상장주식수 변화·가격 불연속 탐지로 누락을 확인하며, 비공식 수정주가는 교차검증에 활용한다.**
- **근거:** A만으로는 분할·병합과 유상·무상증자 등 서로 다른 기업행위를 안정적으로 구분하기 어렵다. B만으로는 공시 파싱 누락이나 실제 효력일 처리 오류가 남을 수 있다. C는 구현이 간단하지만 외부 소스의 산식과 커버리지에 의존한다. D는 독립적인 탐지와 근거 확인을 조합한다.
- **보완:** 가격 조정계수와 효력일을 기업행위별로 기록하고, 수정 전·후 가격 및 주식 수의 연속성 테스트를 만든다. 배당 미포함 모멘텀과 총수익률을 혼동하지 않도록 지표 정의를 고정한다.
- **반증 조건:** 공시 자료의 자동 파싱이 불완전하거나 수작업 확인 비용이 지나치게 크면, 검증된 외부 가격 데이터의 사용 조건·수정 이력을 검토한다. 검증 전에는 해당 종목의 모멘텀과 백테스트 성과를 유효한 값으로 취급하지 않는다.
- **확신도: 중**

## Q9. 1단계 착수 범위

- **선택: A — 표본 20~30개사로 수집→정규화→점수의 전체 흐름을 검증한 뒤 전 종목으로 확장한다.**
- **근거:** 가장 큰 불확실성은 단순 수집량보다 다양한 계정 구조, 결산월, 정정공시, 기업행위에서 계산이 올바른지 여부다. 처음부터 전 종목을 구축하면 잘못된 규칙을 대규모로 적용하고 디버깅할 수 있다. C는 시세 파이프라인을 별도로 만들 수 있지만, 핵심인 재무 정규화와 점수의 종단 검증을 미룰 수 있다.
- **보완:** 표본은 대형주만으로 구성하지 않는다. 적자·비12월 결산·정정공시·비표준 계정·지배주주와 비지배주주 차이가 큰 기업·상장폐지 기업·기업행위 사례를 포함한다. 20~30개는 초기 게이트 표본이지, 전체 시장의 품질을 통계적으로 보증하는 표본은 아니다.
- **1단계 완료 기준 추가 제안:**
  1. 표본 기업의 핵심 계정과 파생지표를 독립 수작업 계산과 대조하고 허용오차·실패 기준을 명시한다.
  2. 누적/3개월 금액, 4분기 역산, TTM, 연결/별도, 지배주주 항목의 테스트를 자동화한다.
  3. 정정공시·공시 시점·수집 지연을 포함한 시점 재현 테스트를 통과한다.
  4. 기업행위 조정과 상장폐지 처리에 대해 테스트 사례와 미지원 범위를 문서화한다.
  5. API 실패·한도 초과·빈 응답·중복 응답에서도 마지막 정상본을 보존하고 상태를 표시한다.
  6. 각 필수 데이터 항목의 커버리지와 결측률을 보고하고, 미충족 항목은 순위 산정에서 명시적으로 제외한다.
- **반증 조건:** 전 종목 수집을 먼저 수행하는 것이 오히려 검증 표본의 대표성을 높이고 추가 구현 비용을 거의 발생시키지 않는다는 실측이 나오면 B를 재검토한다.
- **확신도: 상**

## Q10. 상장폐지 이력 소스

- **선택: C — KIND 상장폐지현황의 자동 수집 가능성을 확인해 공식 주 소스로 삼고, KRX 과거 시세와 비공식 목록으로 교차검증한다.**
- **근거:** 상장폐지일·사유와 관련 이력을 가능한 한 공식 채널에서 재현 가능하게 확보하는 것이 바람직하다. KRX 시세의 마지막 등장일만으로는 폐지일·사유·정리매매·합병 대가를 모두 알 수 없다. FinanceDataReader 목록은 유용한 교차검증 자료지만 비공식 소스 하나에 의존하는 것은 취약하다.
- **보완:** KIND 수집 방식과 과거 커버리지가 확인되기 전에는 C를 확정 구현으로 간주하지 않는다. 공식 소스에 누락이 있으면 A를 보조적으로 적용하되, 출처별 차이와 미해결 건을 별도로 관리한다.
- **반증 조건:** KIND 자료를 안정적으로 자동 수집할 수 없거나 필요한 과거 이력을 제공하지 않고, 비공식 목록이 KRX 시세와 대조했을 때 더 높은 커버리지와 정확도를 보이면 A를 주 소스로 재검토한다.
- **확신도: 중**
