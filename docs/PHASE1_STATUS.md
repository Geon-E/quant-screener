## 수정주가 (D-16) — 2026-10-25

**방식**: KRX 공식 기준가로 조정계수 산출. 조정계수 = (종가 − 전일대비) ÷ 전일 종가. 기업행위가 없는 날은 정확히 1.

| 결과 | 값 |
|---|---|
| 대상 | 2,870종목, 2025-09 ~ 2026-10 |
| 감지 사건 | 884건 — 주식병합 282 · 분할 21 · 권리락 162 · 인적분할·감자 등 78 · SPAC 기준가 상향 334 · 미세 7 |
| 검산 (KRX 등락률과 정합) | 최대 0.005%p (반올림 수준) — 같은 KRX 필드 기반이라 **독립 검증 아님** |
| **독립 교차검증** (FinanceDataReader 수정주가, 80종목) | 사건 있는 74종목의 누적수익률 상대차이 **중앙값 0.000%** |
| 교차검증 이상치 4건 | 에이프로젠·에이프로젠바이오로직스: DART로 **15:1 감자** 확인 → 우리 값이 맞고 비공식 소스가 감자 미반영. 페이퍼코리아: 5:1 병합, 소폭 차이. 선도전기: 아래 |
| 표본 공시 확인 | 확인 필요 사건 14건 중 7건 DART 확인 (나머지 7건은 SPAC 기준가 상향 — 유니버스 제외 대상) |

**발견 — 기준가 변경 ≠ 기업행위**
- 선도전기(2026-04-29): 주식수 변화 없이 기준가가 3,000원 → 5,000원으로 재설정됐다.
- 이런 경우 조정계수로 적용하면 실제 가격 변동을 지우게 된다.
- 현재 정책: 주식수 역수 관계(분할·병합)나 DART 공시로 확인되지 않은 사건이 13개월 안에 있으면 **그 종목의 모멘텀은 무효**. 잘못된 보정으로 값을 만들지 않는다.
- 2단계 백테스트 수익률 계산에서는 미확인 사건을 **보정하지 않는 것**을 기본으로 하고, 해당 종목에 플래그를 붙인다 (4차 협의 안건).

**설계와의 차이 (투명성)**
- D-16 합의 문구는 "공시 기반 보정"이다. 구현은 **거래소 공식 기준가를 주 소스**로, 공시는 사건 확인용으로 쓴다.
- 근거: 공시 문서 파싱보다 거래소가 실제 적용한 수치가 더 정확하고 재현 가능하다.
- 4차 협의에서 이 차이를 확인받는다.

## 원천값 자동 대조 (D-22 변경) — 2026-10-25

**왜 바꿨나**: 사람 확인(사용자·GPT 분담)은 둘 다 DART 원문을 열 수 없어 수행 불가였다 (GPT 62행 전부 미확인, 사용자도 확인 불가).

**무엇과 비교하나** — 우리 계정 선택 규칙(`account_rules.yaml`)을 거치지 않은 값
| 출처 | 항목 | 독립성 |
|---|---|---|
| DART 주요계정 API (`fnlttSinglAcnt`) | 매출액·영업이익·당기순이익·자산·부채·자본총계 | 금감원 자체 추출. 원천 공시는 같음 → **"같은 칸을 골랐는가"** 확인 |
| 사업보고서 배당 항목 (`alotMatter`) | (연결/별도) 당기순이익 = 지배주주 순이익 | 회사가 본문에 따로 적는 값 → 재무표와 **다른 경로** |
| (범위 확인) | 지배주주 자본 ≤ 자본총계 | 외부에 지배 귀속 자본이 없어 독립 대조 불가. `no_nci`·`separate_only` 규칙을 쓴 경우만 자본총계와 직접 비교 |

**대상**: 평가 25개사 × (직전 사업연도 + 기준 분기). **판정**: 단위 반올림 이내 = 정확 일치, 1% 이내, 그 외 = 불일치 → 건별 원인 조사.
**한계**: 회사 공시 자체가 틀렸다면 함께 틀린다. 외부 사이트(FnGuide·네이버)는 자동 수집을 막아 두어 쓰지 않았다.

**KIND robots.txt 확인 불가 — 투명성 기록**
- KIND 방화벽이 robots.txt 요청에 HTML 차단 페이지를 돌려줬는데, 코드가 이를 '허용'으로 잘못 해석해 **KIND를 1회 조회**했다 (관리종목 184행, 상장폐지 730행).
- 버그 수정: robots.txt가 아닌 응답은 '확인 불가' → 수집 안 함 (테스트 추가). KIND는 robots 확인 전까지 사용 중단.

**결론 (4차 협의·사용자 결정 안건)**
- D-19: KRX 상장폐지종목 현황을 공식 폐지일·사유 소스로 쓰는 것이 데이터상 가장 낫다 (원래 역할 분리에서 KIND가 맡던 몫). KRX 시세 마지막 관측일로 교차 확인.
- D-15: 코스피 관리종목의 **과거 이력** 소스가 없다. 선택지는 4차 안건 참조.

## 최초본 XBRL 복원 (D-17) — 2026-10-25

**방법**: 최초 제출본 XBRL을 재무 API와 같은 행 형식으로 바꿔 계정 선택 규칙을 그대로 재사용 (`src/qs/xbrl.py`).
**파서 검증**: 표본 정정 보고서 114건의 최초본을 최신 정정본(API)과 항목별 비교. 정정이 숫자를 바꾸지 않은 보고서가 많아 파서 검증이 된다.

| 결과 | 건수 |
|---|---|
| 정확 일치 | 1,879 |
| 0.5% 이내 | 33 |
| 다름 | 76 — 대부분 한 보고서의 여러 항목이 함께 바뀐 **실제 재작성** (예: 더라미 2015 사업보고서 순이익 최초 −436억 → 정정 −347억) |
| 한쪽만 있음 | 15 |

**검증 중 발견한 버그 2건**
1. 파서: 구형 패키지는 표시 링크베이스에 회사 확장 계정만 담아 '자산총계' 등이 빠짐 → 표준 개념은 기간 유형으로 재무제표 배정 (수정 후 '한쪽만 있음' 517 → 15)
2. **본 파이프라인 계정 선택**: 표준 ID 행이 비어 있으면 비표준 계정(사채·전환사채)을 보지 않고 부채 0으로 처리 → NAVER 2016 3Q 사채 1,500억, 인크레더블버즈 전환사채 132억 누락. 수정 + 테스트. 현재 표본 최신 분기 값에는 영향 없음

**백테스트 적용**: 기준일이 첫 정정 접수일 이전이면 최초본 값, 이후면 정정본 값. 정정이 3회 이상이면 중간본은 복원 못 함(한계). 전 종목 수집기가 정정 보고서의 최초본 XBRL도 받는다.
