## 0. 한 줄 요약

**국내 상장사(코스피·코스닥)의 시세와 재무제표를 공식 API로 자동 수집하고, 같은 업종 안에서 지표상 싸면서 우량하고 나빠지지 않는 종목을 "정량 기준상 저평가 후보"로 골라 근거와 함께 보여주는 시스템.**

- 위험 필터는 가치함정을 *제거하는* 장치가 아니라 *일부 위험을 식별하는* 장치다.
- 결과물은 투자 권유가 아닌 **후보 목록**이다.

예시 출력:

> 삼성전자 | 기준일 2026-11-20 | 비교집단: 반도체 사업군(n=24)
> PER 사업군 중앙값 대비 −25% · F-스코어 7/9 · 데이터 신뢰도 높음 → **정량 기준상 저평가 후보**

## 1. 목표 · 범위 · 원칙

### 1.1 목표
1. **자동 수집**: 파일 업로드 없이 매일 갱신
2. **업종 상대 판정**: "같은 사업군 안에서" 상대적으로 싼가
3. **정확성 우선**: 계산 결과보다 입력 데이터의 시점·정확성을 먼저 보장
4. **검증 가능**: 성과를 사전에 정의한 지표로 측정하고, 검증을 통과한 기능만 사용자에게 노출

### 1.2 우선순위 원칙 (GPT 검토 반영)
```
데이터 정확성·시점 정합성  >  검증 가능한 성과 측정  >  점수 공식의 정교함  >  화면·기능 확장
```

### 1.3 범위
| 포함 (1~3단계) | 보류 (4단계 이후) | 제외 |
|---|---|---|
| 코스피·코스닥 일반 기업 | 미국 시장, 금융업 전용 모델, 고급 차트, 포트폴리오 자동 구성 화면 | 실시간 시세, 기술적 분석, 자동 주문, 목표주가 산출 |

## 2. 전체 아키텍처

브라우저 단독(단일 HTML)으로는 자동 수집이 불가하다.
- KRX 정보데이터시스템은 로그인이 필요하다.
- SEC는 `User-Agent` 지정이 필수이고, CORS를 지원하지 않는다.
- API 키가 노출된다.

그래서 **수집·가공은 서버(GitHub Actions + Python)**, **표시는 정적 화면**으로 나눈다.

### 2.1 데이터 계층 (처음부터 분리)

| 계층 | 내용 | 저장 형식 | 변경 규칙 |
|---|---|---|---|
| L0 원본 | API 응답 그대로 + `collected_at`, `source_hash` | 압축 JSON | **추가만, 수정·삭제 금지** |
| L1 정규화 | 표준 계정·시점 정보(`available_at`)가 붙은 재무·시세 | DuckDB / Parquet | 재생성 가능 (L0에서 결정적으로 생성) |
| L2 점수 | 일자별 전 종목 지표·점수·플래그 + 전략 설정 버전 | Parquet | 일자·전략버전별 불변 |
| L3 배포 | 화면용 상위 종목·업종 요약 | JSON | 매 실행 덮어쓰기 |

- **보관 위치**: L0~L2는 Git 이력에 직접 넣지 않는다. 저장소 용량 제한과 대량 시계열 관리 문제 때문이다. 대신 GitHub Release 자산 또는 별도 저장소에 둔다 (DECISIONS D-12).
- **인터페이스**: 저장소 위치를 나중에 바꿀 수 있도록 `storage.py` 하나로 감싼다.

### 2.2 실행 흐름

```
GitHub Actions (매일, 실측 후 시각 확정 — D-08)
 ① collect   KRX 시세 / DART 공시목록·재무 → L0
 ② normalize 계정 표준화·TTM·PIT 부여        → L1
 ③ check     품질 점검 (4.7) ── 실패 → 배포 중단, 상태 기록
 ④ score     유니버스·지표·점수·플래그        → L2
 ⑤ publish   화면용 JSON                       → L3 (마지막 정상본 유지)
```

- **실행 상태**: 매 실행마다 `run_status.json`을 기록한다.
  - 단계별로 `success`, `api_error`, `rate_limited`, `quality_failed`, `publish_failed`를 구분한다.
  - 화면은 이 파일을 읽어 "데이터 기준일·갱신 성공 여부"를 항상 표시한다.
- **비밀값**: KRX·DART 키는 GitHub Secrets에 둔다.

## 3. 데이터 소스

| 구분 | 소스 | 받는 것 | 조건 (확인된 범위) |
|---|---|---|---|
| 시세 | KRX OPEN API `sto/stk_bydd_trd`, `sto/ksq_bydd_trd` | 일별 종가·시가·시총·상장주식수·거래대금 | 인증키 발급 + **서비스별 이용신청·관리자 승인** 필요 (이 프로젝트는 당일 승인). 호출: `https://data-dbg.krx.co.kr/svc/apis/{api}?basDd=YYYYMMDD`, 헤더 `AUTH_KEY` |
| 지수 | KRX OPEN API `idx/kospi_dd_trd`, `idx/kosdaq_dd_trd` | 벤치마크 지수 | 위와 동일 |
| 종목정보 | KRX OPEN API 종목기본정보 | 시장구분·소속부·주식종류 | 위와 동일 |
| 재무 | OpenDART `fnlttSinglAcntAll` | 분기별 전체 재무제표 | 2015년 이후. 요청 한도 초과 시 오류 020 (가이드상 일반적으로 2만 건 수준, **발급 키별 실제 조건 확인 필요**). 다중회사 조회는 100개사 제한 |
| 공시 시점 | OpenDART `list.json` | `rcept_no`, `rcept_dt`, 보고서명(정정 여부) | 위와 동일 |
| 업종 | OpenDART 기업개황 | `induty_code` (KSIC) | 위와 동일 |
| 상장폐지 이력 | FinanceDataReader `KRX-DELISTING` (비공식) + KRX 일별시세 마지막 등장일 (공식, 교차검증) | 폐지일·사유·이전 코드 | 0단계 확인: 4,211건 |
| 수정주가·기업행위 | **직접 계산** (KRX는 원 종가만 제공) | 분할·병합·증자 보정 | 방식은 D-16 |
| 코스피 관리종목 | **소스 미정** (코스닥은 종목기본정보에 표시됨) | 관리종목 여부 | D-15 |

**0단계 실측 결과**: 시세는 2010년 이후, 재무는 2015 사업연도 이후 조회 가능하다. 과거 시세에는 상장폐지 종목이 포함되어 있다. 상세는 [`PHASE0_FINDINGS.md`](PHASE0_FINDINGS.md).

미국(SEC EDGAR 등)은 4단계로 보류한다. SEC 조건은 초당 10회 이하, User-Agent 필수, CORS 미지원이다.

**호출량 계획**
- 최초 적재는 호출 한도·응답 실패·재시도를 고려해 며칠로 분할한다.
- 이후에는 신규 공시분만 증분 수집한다.
- 모든 호출 결과(실패 포함)를 L0에 기록한다.

## 4. 데이터 가공 규칙

### 4.1 시점 정합성 (Point-in-Time)

**재무 레코드 필수 필드**

| 필드 | 의미 |
|---|---|
| `rcept_no` | 공시 접수번호 |
| `rcept_dt` | 접수일 |
| `report_type` | 사업·반기·분기 / 최초·정정 |
| `amends` | 정정 대상 원 접수번호 (정정공시일 때) |
| `available_at` | 전략에서 사용 가능해지는 시각 = **접수일 다음 영업일 장 시작 전** (보수적 규칙, 접수 시각을 확보하면 정교화) |
| `collected_at` | 실제 수집 시각 |
| `source_hash` | L0 원본 식별 해시 |

**사용 규칙**
- 기준일 D의 점수는 `available_at ≤ D 장 마감`인 데이터만 사용한다.
- 정정공시는 정정 `available_at` 이후에만 반영한다.
- **소급 금지**: 수집이 늦었다고 과거 일자의 L2 점수를 최신 재무로 다시 쓰지 않는다. 재계산이 필요하면 새 전략 버전으로 별도 생성한다.

**두 가지 관점**
- `as_reported`: 그 시점에 공개된 최신본 (정정 전 값 포함)
- `latest`: 현재 기준 최종 정정본

백테스트 기본값은 `as_reported`다.

**구현 경로 (0단계 실측으로 확정 — [`PHASE0_FINDINGS.md`](PHASE0_FINDINGS.md))**
- 재무 API(`fnlttSinglAcntAll`)는 정정 후 **최신본** 값을 반환한다 (표본 6/6).
- 최초본은 **접수번호별 원본 XBRL**(`fnlttXbrl.xml`)로 복원할 수 있다.
- 적용 순서:
  - 1단계: 정정공시가 있는 기업만 XBRL 최초본을 확보한다.
  - 2단계: 백테스트 구간 전체에 적용한다.
- 복원에 실패한 건은 `latest`로 대체하고 플래그를 붙인다.

### 4.2 계정 표준화 규칙 (`config/account_rules.yaml`)

계정명 사전이 아니라 **규칙 단위**로 관리한다.

| 속성 | 예 |
|---|---|
| 표준 계정 ID | `NI_OWNERS` (지배기업 소유주지분 순이익) |
| 허용 원본 | `account_id` 목록(우선), 계정명 패턴(보조) |
| 재무제표 종류 | IS / CIS / BS / CF |
| 연결·별도 | CFS / OFS |
| 금액 종류 | 누적(`thstrm_add_amount`) / 3개월(`thstrm_amount`) / 잔액 |
| 부호 규칙 | 비용 계정의 음수 표시 처리 |
| 유효기간 | 회계기준·계정체계 변경 시점 |
| 신뢰도 | `verified`(표본 검증 완료) / `pattern`(패턴 매칭) / `fallback` |

**지배주주 규칙 (v0.1에서 변경)**
| 상황 | 처리 |
|---|---|
| 연결재무제표 있음 + 지배주주 항목 식별됨 | 지배주주 값 사용 |
| 연결재무제표 있음 + 지배주주 항목 식별 불가 | 전체 값으로 **대체하지 않음** → 해당 지표 무효, 신뢰도 "낮음" |
| 연결 대상 없음 (별도재무제표만 존재) | 전체 = 지배주주로 간주 (유효) |

- 연결·별도를 한 기업 안에서 혼용하지 않는다 (`fs_div` 기록).
- **계정 매핑 검증 표본 20~30개사**:
  - 대형주(삼성전자·현대차 등)
  - 적자 기업
  - 지배·비지배 차이가 큰 기업
  - 계정 구조가 복잡한 기업
  - 결산월이 12월이 아닌 기업
  - 정정공시가 있는 기업
- 표본은 수작업 계산과 대조한다 (`tests/fixtures/`).

### 4.3 TTM
- 손익·현금흐름: 누적 금액과 3개월 금액을 구분해 분기값을 복원한 뒤 최근 4개 분기를 합산한다.
  - 4분기 = 연간 − 3분기 누적
- 재무상태표: 최근 분기말 잔액. 평균이 필요한 지표는 기초·기말 평균을 쓴다.
- 결산월이 12월이 아닌 기업, 분기 결측, 회계기준 변경 시점은 **해당 TTM을 무효 처리**한다. 4개 분기가 연속으로 확보되지 않으면 계산하지 않는다.

### 4.4 시가총액
- 보통주 시총 + 같은 회사 우선주 시총 (종목코드 앞 5자리 동일).
- 우선주는 독립 순위에 넣지 않는다.

### 4.5 EV
- EV = 시총 + 이자부부채(차입금·사채·리스부채) − 현금성자산 − 단기금융상품
- 각 구성 계정도 4.2 규칙으로 관리한다.

### 4.6 지표 유효성 규칙 (무효 ≠ 0점)

무효인 지표는 **점수 산정 대상에서 제외**하고 사유를 기록한다.

| 지표 | 무효 조건 | 상태 표시 |
|---|---|---|
| B/P, ROE, PBR–ROE 잔차 | 지배주주 자본 ≤ 0 | `자본잠식` (순위 제외) |
| ROE | 평균 자본이 시총의 1% 미만 등 극소 분모 | `분모 불안정` |
| E/P | 계산은 유효 (적자면 음수) | PER 표시는 흑자만 |
| EBITDA/EV | EV ≤ 0 또는 EV < 시총의 10% | `EV 비정상` |
| 이익의 질 (CFO/NI) | 순이익 ≤ 0 | 이 지표 무효 |
| 이자보상배율 | 이자비용 = 0 | 상한값(예: 100배)으로 고정 (무차입 = 우량) |
| `log(PBR)` | PBR ≤ 0 | 회귀 표본에서 제외 |

- **이상치 처리**: 업종 내 백분위 변환 전, 각 지표를 사업군별 1%·99% 분위로 윈저라이징한다. 기준은 전략 버전 v1에 고정한다.

### 4.7 데이터 품질 점검

| 수준 | 점검 | 실패 시 |
|---|---|---|
| 응답 | HTTP·API 상태코드, 레코드 수가 전일 대비 ±5% 이내, 빈 응답 | 재시도 → 실패 시 `api_error` |
| 레코드 | 종목코드 중복·누락, 숫자 변환 실패, 필수 필드 결측 | `quality_failed` |
| 교차 | 시총 ≈ 종가 × 상장주식수 (±1%), 우선주 매칭 | 해당 종목 플래그, 비율 초과 시 실패 |
| 시계열 | 같은 기업 재무가 직전 공시 대비 10배 이상 변동, 부호 반전 | 원본 재확인 큐에 등록, 해당 종목 신뢰도 하향 |
| 분포 | 사업군별 지표 중앙값의 전일 대비 급변 | 경고 |
| 단위 | 소스별 PER 중앙값이 과거 범위를 크게 벗어남 | 경고 (단독으로 실패 판정 안 함) |

**원칙**
- 오류 데이터를 이전 값으로 **조용히 대체하지 않는다.**
- 화면은 마지막 정상 데이터를 보여주되 "갱신 실패" 상태를 함께 표시한다.

## 5. 점수 체계 (전략 설정 v1)

모든 설정은 `config/strategy_v1.yaml`에 고정한다. 바꿀 때는 버전을 올리고 [`EXPERIMENTS.md`](EXPERIMENTS.md)에 기록한다.

### 5.1 유니버스
| 조건 | 기본값 |
|---|---|
| 시장 | 코스피·코스닥 |
| 시가총액 | ≥ 500억 원 |
| 20일 평균 거래대금 | ≥ 5억 원 |
| 제외 | 관리종목·거래정지·투자주의환기·스팩·리츠·금융업(D-06)·상장 1년 미만 |
| 경고 | 지주회사 |

### 5.2 비교 사업군 (v0.1에서 변경)
- KSIC(`induty_code`)를 기반으로 **사람이 사전에 묶은 고정 표** `config/peer_groups_v1.csv`를 쓴다.
  - 사업군 ID, 포함 KSIC 코드, 묶은 이유, 적용일을 기록한다.
- **실행 중 종목 수에 따른 자동 병합은 하지 않는다.** 시점마다 비교 집단이 바뀌면 재현성이 깨지기 때문이다.
- 표본 수에 따른 점수 신뢰도:

| n | 신뢰도 |
|---|---|
| ≥ 15 | 높음 |
| 10~14 | 보통 |
| < 10 | 낮음 (순위에는 포함, 화면에 표시) |

- 개별 종목 보정은 `config/peer_overrides.csv`에 기록한다 (적용일·사유·이전 분류).
- 화면에 사업군 이름과 표본 수를 항상 표시한다.
- **비교 실험** (7.5): 사업군 표 vs KSIC 원분류 vs 전체 시장

### 5.3 지표 (v1)

지표 수 자체는 기준이 아니다. 각 지표가 **추가로 주는 정보**를 7.5 실험으로 평가한다.

| 묶음 | 지표 | 산식 | 방향 |
|---|---|---|---|
| 가치 | E/P | 지배주주 TTM 순이익 ÷ 시총 | ↑ |
| | B/P | 지배주주 자본 ÷ 시총 | ↑ |
| | EBITDA/EV | (TTM 영업이익 + TTM 감가상각비) ÷ EV | ↑ |
| | PBR–ROE 잔차 | 사업군 내 `log(PBR) = a + b·ROE` 잔차 (유효 표본 ≥ 15일 때만) | 음수일수록 ↑ |
| 퀄리티 | ROE | 지배주주 TTM 순이익 ÷ 평균 지배주주 자본 | ↑ |
| | GP/A | TTM 매출총이익 ÷ 평균 총자산 | ↑ |
| | 이익의 질 | TTM 영업현금흐름 ÷ TTM 순이익 | ↑ |
| 추세 | 12-1 모멘텀 | **수정주가 기준** 12개월 전 ~ 1개월 전 수익률 (배당 미포함, v1) | ↑ |
| | 이익 모멘텀 | TTM 영업이익 전년동기 대비 증감률 | ↑ |
| 안정성 | 이자보상배율 | TTM 영업이익 ÷ TTM 이자비용 | ↑ |

**PBR–ROE 잔차 표시 규칙**
- 잔차를 할인율로 표시할 때는 `exp(잔차) − 1`로 변환한다.
- 화면 문구는 "회귀 기준 예상 PBR 대비 −x%"로 쓴다. "시장에서 저평가"라고 표현하지 않는다.
- 사업군의 회귀 결정계수(R²)가 0.1 미만이면 이 지표를 그 사업군에서 비활성화한다.

**모멘텀 데이터 조건**: 13개월 가격 이력이 없으면 무효 (신규 상장 종목).

### 5.4 묶음 점수와 결측 처리 (v0.1에서 변경)

1. 각 지표를 사업군 내 백분위(0~100)로 변환한다 (유효값만).
2. 묶음 점수 = 유효 지표 백분위의 평균.
3. **묶음별 최소 충족 조건**

| 묶음 | 최소 조건 | 미충족 시 |
|---|---|---|
| 가치 | E/P와 B/P 중 1개 이상 포함, 4개 중 2개 이상 유효 | **종합 순위 제외** |
| 퀄리티 | 3개 중 2개 이상 | 종합 순위 제외 |
| 추세 | 2개 중 1개 이상 | 종합 순위 제외 |
| 안정성 | 1개 | 종합 순위 제외 |

4. **데이터 없음 ≠ 중립 50점**: 결측을 50점으로 채우지 않는다.
5. 제외된 종목은 수와 특성(시총 구간·사업군)을 기록한다. 제외 자체가 만드는 편향도 감시하기 위해서다.
6. 종목마다 **데이터 완전성(%), 신뢰도(높음·보통·낮음), 최근 재무 기준일**을 점수와 별도로 표시한다.

### 5.5 종합 점수
```
종합 = 가치 40% + 퀄리티 30% + 추세 20% + 안정성 10%   (v1 초기 가설)
```
- 이것은 **합리적 가설이지 검증된 최적값이 아니다.** 문서·화면에서도 그렇게 표기한다.
- 대안 모델과의 비교는 7.5에서 한다.

### 5.6 위험 필터 — 순위 제외와 경고를 구분

| 구분 | 조건 | 처리 |
|---|---|---|
| 제외 | 자본잠식 (지배주주 자본 ≤ 0) | 순위 제외 |
| 제외 | TTM 지배주주 순이익 < 0 | 순위 제외 (v1) — 실험에서 포함 버전과 비교 |
| 제외 | F-스코어 ≤ 3 (유효 항목 7개 이상일 때) | 순위 제외 (v1) — 실험에서 제외 전후 비교 |
| 경고 | 순이익 > 영업이익 × 1.5 (영업이익 > 0) | 일회성 이익 의심 |
| 경고 | 순이익 > 0 이면서 영업현금흐름 < 0 (2개 분기 연속) | 이익의 질 |
| 경고 | 부채비율(총부채 ÷ 자본) 사업군 상위 10% | 부채 |
| 경고 | 지주회사 | 구조적 할인 |
| 경고 | 거래대금 유니버스 하위 10% | 유동성 |

**F-스코어 정의 (v1)**: 비교는 TTM 기준 당기 vs 1년 전 TTM.

| # | 항목 | 1점 조건 | 결측 처리 |
|---|---|---|---|
| 1 | 수익성 | ROA(순이익 ÷ 기초자산) > 0 | 항목 무효 |
| 2 | 현금흐름 | 영업현금흐름 > 0 | 항목 무효 |
| 3 | 수익성 개선 | ROA 당기 > 전년 | 항목 무효 |
| 4 | 이익의 질 | 영업현금흐름 > 순이익 | 항목 무효 |
| 5 | 레버리지 | 장기차입금 ÷ 평균자산 당기 < 전년 (장기차입금 0→0이면 1점) | 계정 누락은 무효 (0점 처리 금지) |
| 6 | 유동성 | 유동비율 당기 > 전년 | 항목 무효 |
| 7 | 희석 | 보통주 발행주식수 당기 ≤ 전년 | 항목 무효 |
| 8 | 마진 | 매출총이익률 당기 > 전년 | 항목 무효 |
| 9 | 효율 | 자산회전율 당기 > 전년 | 항목 무효 |

- 점수 = 1점 항목 수 / 유효 항목 수 × 9 (유효 항목이 7개 미만이면 F-스코어 무효)
- 금융업에는 적용하지 않는다.
- F-스코어와 다른 위험 필터가 같은 기업을 중복 제외하는 비율을 매 실행 기록한다.

### 5.7 판정 문구 규칙
- PER 할인율 문구는 **유효한 흑자 기업에만** 쓴다.
- 문구마다 기준일·비교 사업군·표본 수를 붙인다.
- 상위 판정 문구: "정량 기준상 저평가 후보". "안전한", "추천" 같은 표현은 금지한다.

## 6. 포트폴리오 실행 규칙 (검증·추적용 모델 포트폴리오)

### 6.1 구성
| 항목 | v1 |
|---|---|
| 종목 수 | 20 |
| 비중 | 동일 비중 |
| 사업군 한도 | **종목 수 3개 이하 AND 비중 25% 이하** (동시 적용) |
| 유동성 한도 | 종목별 주문 금액 ≤ 20일 평균 거래대금의 5% (기준 운용금액은 설정값) |
| 교체 버퍼 | 보유 종목은 순위 상위 30위 이내면 유지 |

### 6.2 체결 가정
- 신호: 기준일 D **장 마감 후** 데이터로 산출한다.
- 체결: **D+1 시가**를 기본으로 한다. 민감도 분석으로 D+1 종가도 계산한다.
- 거래정지 종목: 정지 기간 동안 보유를 유지하고, 재개 첫날 시가로 처리한다.
- 상장폐지 종목: 정리매매 최종가로 처리한다. 확보 불가 시 **−100%** 로 보수적 처리한다.

### 6.3 리밸런싱 일자
- 일자는 **규칙으로 고정**한다: 정기보고서 법정 제출기한(분기·반기 45일, 사업 90일) 경과 후 **5영업일째**.
- 각 기업의 데이터는 그 시점에 `available_at`이 도래한 것만 쓴다. 늦게 공시한 기업은 직전 데이터를 사용하고 플래그를 붙인다.
- 제출기한에 예외가 적용되는 기업이 있을 수 있다 (0단계 확인).

### 6.4 거래비용 시나리오
| 시나리오 | 편도 비용 가정 (설정값) |
|---|---|
| 낙관 | 수수료 + 거래세 |
| 기준 | 낙관 + 스프레드 절반 |
| 보수 | 기준 + 시장충격 (거래대금 대비 주문 비중에 비례) |

## 7. 검증 계획

### 7.1 성과 지표 (사전 고정)
- 비용 차감 전·후 CAGR, 누적수익률
- 최대낙폭(MDD), 변동성, 샤프비율
- 회전율, 연간 거래비용
- 벤치마크 대비 초과수익: (a) 유니버스 동일비중, (b) 코스피·코스닥 지수
- **적중률**: 편입 종목 중 다음 기간에 소속 사업군 평균을 초과한 비율
- **IC**: 시점별 종합점수 vs 다음 3개월 수익률 순위상관. 평균·표준편차·IR(평균 ÷ 표준편차)·표본 수를 함께 기록
- 노출 분석: 업종 비중, 시가총액 구간, 시장 베타, 시장 국면(상승·하락·횡보)별 성과
- 팩터 기여도: 묶음별 단독 성과, 종합 대비 추가 기여

### 7.2 백테스트 인정 조건

아래가 충족되지 않으면 결과를 **"탐색적 분석"** 으로만 표기한다. "검증 완료"라고 하지 않는다.

- [ ] 상장폐지 종목을 포함한 시점별 유니버스
- [ ] 상장일·상장폐지일·거래정지·재개 이력
- [ ] 상장폐지 수익률 처리 (6.2)
- [ ] 종목코드 변경·합병·분할·이전상장 처리
- [ ] 수정주가 (액면분할·유상증자 등)
- [ ] 시점 정합 재무 (4.1, 최소한 `latest` + 한계 표기)
- [ ] 시점 정합 업종 분류 (최소한 현재 분류 사용 + 한계 표기)

### 7.3 기간 분리
- **개발 구간** 2015~2021, **검증 구간** 2022~
- 검증 구간은 전략 버전을 확정한 뒤에 실행한다. 실행할 때마다 열람 횟수를 EXPERIMENTS.md에 기록한다.
- 보조로 워크포워드를 쓴다: 3년 개발 → 1년 평가를 1년씩 이동.

### 7.4 실험 관리 — 과최적화 방지
- **전략의 일부로 간주해 버전 관리하는 것**: 유니버스, 사업군 표, 지표 정의, 이상치 처리, 결측 규칙, 위험 필터, 가중치, 리밸런싱 규칙
- 모든 실험은 [`EXPERIMENTS.md`](EXPERIMENTS.md)에 기록한다: 가설, 변경 내용, 결과, 채택 여부.
- 기록 없는 설정 변경은 금지한다.

### 7.5 비교 실험 목록 (개발 구간에서만)
- 가중치: 동일가중 / 가치 중심 / 가치·퀄리티 / 묶음 하나씩 제외(4종) / 묶음 내 대표 지표 1개로 축소
- 사업군: 고정 사업군 표 / KSIC 원분류 / 전체 시장
- 필터: 적자 제외 vs 포함, F-스코어 제외 vs 미적용
- 결측: 보수적 제외(v1) vs 묶음 내 평균 허용

### 7.6 실전 추적
- 1단계 가동일부터 L2에 전 종목 점수를 매일 저장한다.
- 리밸런싱일마다 모델 포트폴리오를 기록한다.
- 재량 운영(D-04)을 하면, 사람이 뺀 종목과 사유를 기록해 순수 모델과 성과를 비교한다.

### 7.7 알려진 한계
- 가치 팩터는 수년간 부진할 수 있다.
- 과거 최초 공시 값의 복원 가능성은 미확인이다.
- 업종 분류는 현재 시점 기준일 수 있다.
- 위험 필터는 경쟁력 약화, 산업의 구조적 쇠퇴, 자본 배분 실패를 탐지하지 못한다.
