## 0. 한 줄 요약

**매일 자동으로 국내(코스피·코스닥)·미국 상장사의 시세와 재무제표를 무료 공식 API로 수집하고, 같은 업종 안에서 지표상 싸면서 우량하고 나빠지지 않는 종목을 기계적으로 골라주는 시스템.**

예시 출력:

> 삼성전자 | 현재가 ○○원 | 시총 ○○조 | 업종 PER 중앙값 대비 −25% | 업종 내 ROE 대비 PBR 저평가 | F-스코어 7/9 → **저평가 후보**

## 1. 목표와 범위

### 1.1 목표
1. **자동 수집**: 파일 업로드 없이 매일 데이터가 갱신된다.
2. **업종 상대 판정**: "시장 전체에서 싸다"가 아니라 "**같은 업종 안에서** 싸다"를 판정한다.
3. **가치함정 회피**: 싼 데는 이유가 있는 종목(적자 전환, 이익 질 악화, 부채 급증)을 걸러내거나 경고한다.
4. **검증 가능**: 첫날부터 결과를 기록해, 규칙이 실제로 통하는지 숫자로 확인한다.

### 1.2 범위 밖 (의도적으로 하지 않는 것)
- 실시간 시세, 단타 신호, 차트 기술적 분석
- 자동 주문 (매매는 사람이 직접)
- 개별 종목 목표주가 산출 (DCF 등)

### 1.3 퀀트 정의상 위치
| 요소 | 의미 | 본 설계 |
|---|---|---|
| 규칙 기반 | 데이터·공식으로 판단 | ✅ 업종 중립 멀티팩터 점수 |
| 넓은 유니버스 | 전 종목 동일 기준 | ✅ 코스피·코스닥(1단계), 미국(2단계) |
| 검증 | 백테스트·실전 추적 | ✅ 성과 추적(1단계) → 백테스트(3단계) |
| 실행 규칙 | 종목 수·주기·비중 | ✅ 6장 포트폴리오 규칙 |

운영 방식(순수 퀀트 vs 후보 중 재량 선택)은 [`DECISIONS.md`](DECISIONS.md) D-04에서 결정.

## 2. 전체 아키텍처

브라우저 단독(단일 HTML)으로는 자동 수집이 불가능하다.
- KRX 정보데이터시스템은 로그인 필요로 바뀜 → 공식 **KRX OPEN API** 사용
- SEC EDGAR는 연락처가 담긴 `User-Agent` 헤더 필수 → 브라우저에서 설정 불가
- API 키를 HTML에 넣으면 노출됨

따라서 **수집기(서버, Python) + 화면(정적 HTML)** 으로 분리한다.

```
┌──────────────────────── GitHub Actions (매일 스케줄 실행, 무료) ────────────────────────┐
│                                                                                       │
│  [collector/]  수집                                                                    │
│   ├─ krx.py      KRX OPEN API   → 종가·시총·상장주식수·거래대금·시장구분 (코스피·코스닥)        │
│   ├─ dart.py     OpenDART       → 분기 재무제표·공시 접수일·업종코드(KSIC)                  │
│   ├─ sec.py      SEC EDGAR      → 미국 재무(XBRL)·SIC 업종코드  (2단계)                    │
│   └─ us_price.py 미국 주가 소스  → 종가·시총 (2단계, 소스는 D-02에서 결정)                    │
│                          ↓  data/raw/ (캐시)                                           │
│  [engine/]  가공·점수                                                                  │
│   ├─ metrics.py  TTM·지배주주·우선주 시총 합산·EV·각종 비율                                │
│   ├─ sector.py   업종 매핑·그룹 크기 보정·수동 보정표                                       │
│   ├─ fscore.py   피오트로스키 F-스코어                                                   │
│   ├─ filters.py  유니버스·위험 필터                                                      │
│   ├─ scoring.py  업종 중립 백분위·PBR-ROE 잔차·종합점수                                    │
│   └─ checks.py   단위·이상치 점검 (실패 시 배포 중단)                                       │
│                          ↓                                                            │
│  [data/latest/]  stocks_kr.json · sectors_kr.json · meta.json                          │
│  [data/history/] 일별 순위 스냅샷 (성과 추적용)                                           │
└───────────────────────────────────────────────────────────────────────────────────────┘
                           ↓  GitHub Pages (또는 raw JSON)
                  [web/index.html]  JSON만 읽어서 표시 — 키·업로드 없음
```

**비밀값 관리**: KRX·DART 키는 GitHub Secrets에 저장. 코드·화면에 노출하지 않는다.

**저장소 공개 범위 주의**: Private 저장소의 GitHub Pages는 요금제 제약이 있을 수 있다. 화면 배포 방식은 [`DECISIONS.md`](DECISIONS.md) D-07에서 결정.

## 3. 데이터 소스

| 구분 | 소스 | 받는 것 | 조건 | 단계 |
|---|---|---|---|---|
| 국내 시세 | KRX OPEN API (`sto/stk_bydd_trd`, `sto/ksq_bydd_trd`) | 일별 종가, 시총, 상장주식수, 거래대금 | 무료. 인증키 발급 후 **서비스별 이용신청·승인** 필요(약 1일) | 1 |

| 국내 재무 | OpenDART `fnlttSinglAcntAll` | 분기별 전체 재무제표 (연결/별도) | 무료, 키 필요. 2015년 이후 제공. 일일 호출 한도 있음(약 2만 건) | 1 |
| 국내 공시일 | OpenDART `list.json` | 보고서 접수일 `rcept_dt` (시점 정합성용) | 위와 동일 | 1 |
| 국내 업종 | OpenDART 기업개황 `company.json` | `induty_code` (KSIC) | 위와 동일 | 1 |
| 미국 재무 | SEC EDGAR `companyfacts` / `frames` | XBRL 재무 | 무료, 키 불필요. `User-Agent` 필수, 초당 10회 이하 | 2 |
| 미국 업종 | SEC `submissions` | SIC 코드 | 위와 동일 | 2 |
| 미국 주가 | (D-02에서 결정) | 종가, 시총 | 무료 소스는 비공식 | 2 |

### 3.1 호출량 관리
- DART 재무는 **분기 공시 시즌에만 증분 수집**하고 나머지는 캐시 재사용 (평상시 일일 호출은 신규 공시분만).
- 최초 1회 전체 적재(약 2,500개사 × 최근 8개 분기)는 일일 한도를 고려해 며칠에 나눠 실행.
- 모든 원본 응답은 `data/raw/`에 캐시 (재계산 시 재호출 불필요).

### 3.2 갱신 시점
- 시세: 장 마감 후 1일 1회. 정확한 실행 시각은 KRX OPEN API의 데이터 제공 시점 확인 후 확정 (D-08).
- 재무: 매일 `list.json`으로 신규 정기보고서 확인 → 있으면 해당 기업만 재수집.

## 4. 데이터 가공 규칙 (정확성의 핵심)

v2.0 분석에서 발견된 왜곡 요인을 처음부터 차단한다 (상세: [`V2_REVIEW.md`](V2_REVIEW.md)).

### 4.1 시점 정합성 (Look-ahead bias 차단)
- 재무 수치는 **결산일이 아니라 공시 접수일(`rcept_dt`) 다음 영업일부터** 사용 가능한 것으로 취급.
- 법정 제출 기한: 분기·반기보고서는 기간 종료 후 45일, 사업보고서는 90일.
- 성과 추적·백테스트 모두 이 규칙을 따른다.

### 4.2 TTM (최근 4개 분기 합)
- 손익·현금흐름: 누적 금액(`thstrm_add_amount`)과 3개월 금액(`thstrm_amount`)을 구분해 분기값을 복원 → 최근 4개 분기 합산.
  - 4분기 값 = 사업보고서 연간 − 3분기 누적
- 재무상태표: 가장 최근 분기말 잔액.

### 4.3 연결·지배주주 기준
- **연결재무제표(CFS) 우선**, 없으면 별도(OFS). 행마다 `fs_div` 기록, 혼용 금지.
- 순이익은 **지배기업 소유주지분 순이익**, 자본은 **지배기업 소유주지분**을 사용 (PER·ROE·PBR 공통).
- 지배주주 항목이 없으면 전체 값을 쓰고 `quality_flag`에 표시.

### 4.4 시가총액
- 보통주 시총 + **같은 회사 우선주 시총 합산** (종목코드 앞 5자리가 같고 끝자리가 0이 아닌 종목).
- 우선주는 독립 종목으로 순위에 넣지 않는다.

### 4.5 EV (기업가치)
- EV = 시가총액 + 이자부부채(단기차입금·사채·장기차입금·리스부채) − 현금및현금성자산 − 단기금융상품
- 이자부부채 계정명은 기업별로 다르므로 계정 매핑표(`config/account_map.yaml`) 관리.

### 4.6 단위·이상치 점검 (`checks.py`)
- 소스별 PER 중앙값이 5~50배 범위를 벗어나면 **배포 중단 + 알림** (단위 오류 가능성).
- 전일 대비 종목 수가 10% 이상 변하면 경고.
- 개별 종목: PER > 1,000, PBR > 100 등 극단값은 계산에는 넣되 화면에 표시.

## 5. 점수 체계

### 5.1 유니버스 (기본값, 설정에서 조정 가능)
| 조건 | 기본값 | 이유 |
|---|---|---|
| 시장 | 코스피·코스닥 | 코넥스는 유동성 부족 |
| 시가총액 | ≥ 500억 원 | 체결 가능성 |
| 20일 평균 거래대금 | ≥ 5억 원 | 체결 가능성 |
| 제외 | 관리종목·거래정지·투자주의환기·스팩·리츠·우선주(보통주에 합산) | 정상 기업만 비교 |
| 제외 | 상장 1년 미만 | TTM 재무 불충분 |
| 별도 처리 | 금융업(은행·보험·증권) | 부채·매출 개념이 달라 일반 기업과 비교 불가 (D-06) |
| 경고 표시 | 지주회사 | 지주사 할인으로 구조적으로 싸 보임 |

### 5.2 업종 분류
- 국내: DART `induty_code`(KSIC) 기준.
- **그룹 크기 보정**: KSIC 소분류(3자리) 기준 종목 수 ≥ 10이면 그대로, 미만이면 중분류(2자리)로 상향, 그래도 미만이면 상위 묶음표(`config/sector_groups.csv`)로 통합.
- **수동 보정표** `config/sector_overrides.csv`: 공식 분류가 실제 사업과 어긋나는 종목 교정 (변경 이력 기록).
- 미국(2단계): SIC 4자리 → 2자리 주요그룹 기준, 동일한 크기 보정.
- 대안(WICS 등)은 D-03에서 결정.

### 5.3 지표 구성 — 묶음별 2~3개, 총 10개

모든 지표는 **업종 내 백분위(0~100)** 로 변환 후 사용 (업종 중립).
밸류에이션은 역수(수익률)로 순위를 매겨 적자·자본잠식이 자동으로 최하위가 되게 한다.

| 묶음 | 지표 | 계산 | 방향 |
|---|---|---|---|
| **가치** | 이익수익률 E/P | 지배주주 TTM 순이익 ÷ 시총 | 높을수록↑ |
| | 장부가치 B/P | 지배주주 자본 ÷ 시총 | 높을수록↑ |
| | EBITDA/EV | (TTM 영업이익 + 감가상각비) ÷ EV | 높을수록↑ |
| | **PBR–ROE 잔차** | 업종 내 회귀 `log(PBR) = a + b·ROE` 의 잔차 | 낮을수록(음수)↑ |
| **퀄리티** | ROE | 지배주주 TTM 순이익 ÷ 지배주주 자본(기초·기말 평균) | 높을수록↑ |
| | GP/A | TTM **매출총이익** ÷ 총자산 | 높을수록↑ |
| | 이익의 질 | TTM 영업현금흐름 ÷ TTM 순이익 (적자면 별도 처리) | 높을수록↑ |
| **추세** | 12-1 모멘텀 | 최근 12개월 수익률 − 최근 1개월 수익률 | 높을수록↑ |
| | 이익 모멘텀 | TTM 영업이익 전년동기 대비 증감률 | 높을수록↑ |
| **안정성** | 이자보상배율 | TTM 영업이익 ÷ TTM 이자비용 | 높을수록↑ |

> 부채비율은 업종별 편차가 커서 점수 대신 **위험 필터**(5.5)에서 업종 내 상위 10% 경고로 사용.

### 5.4 종합 점수
```
가치 점수   = 가치 지표 4개 백분위 평균
퀄리티 점수 = 퀄리티 지표 3개 백분위 평균
추세 점수   = 추세 지표 2개 백분위 평균
안정성 점수 = 이자보상배율 백분위

종합 = 가치 40% + 퀄리티 30% + 추세 20% + 안정성 10%
```
- 가중치는 **시작값이며 백테스트로 미세조정하지 않는다** (과최적화 방지). 변경 시 근거를 DECISIONS.md에 기록.
- 결측 지표는 해당 묶음 안의 나머지 지표로 평균. 묶음 전체가 결측이면 50점(중립) + 데이터 부족 플래그.
- 데이터 충족률 70% 미만 종목은 순위에서 제외(표시는 함).

### 5.5 위험 필터 (가치함정 방지)
| 플래그 | 조건 | 처리 |
|---|---|---|
| 🔴 적자 | TTM 지배주주 순이익 < 0 | 순위 제외(기본) |
| 🔴 재무 악화 | F-스코어 ≤ 3 | 순위 제외(기본) |
| 🟠 일회성 이익 | 순이익 > 영업이익 × 1.5 이고 영업이익 > 0 | 경고 |
| 🟠 이익 질 | 영업현금흐름 < 0 이면서 순이익 > 0 (2개 분기 연속) | 경고 |
| 🟠 부채 | 부채비율 업종 내 상위 10% 또는 전년 대비 +50%p | 경고 |
| 🟠 지주사 | 업종코드·사명 기준 | 경고 |
| 🟡 유동성 | 거래대금 하위 10% | 경고 |

**피오트로스키 F-스코어 (9점)**: ROA>0, 영업현금흐름>0, ROA 개선, 영업현금흐름>순이익, 장기부채비율 감소, 유동비율 개선, 신주 발행 없음, 매출총이익률 개선, 자산회전율 개선.

### 5.6 판정 문구 자동 생성
종목마다 근거 문장을 붙인다. 예:
- "업종(반도체) PER 중앙값 대비 −25%, PBR 중앙값 대비 −18%"
- "같은 ROE 수준 대비 PBR이 업종 회귀선보다 30% 낮음"
- "F-스코어 7/9, 영업이익 전년 대비 +12%"
- "⚠ 순이익이 영업이익의 1.8배 — 일회성 이익 확인 필요"

## 6. 포트폴리오 실행 규칙

| 항목 | 기본값 | 비고 |
|---|---|---|
| 종목 수 | 20~30 | 분산으로 개별 종목 오류 상쇄 |
| 비중 | 동일 비중 | 단순·견고 |
| 업종 한도 | 업종당 최대 3종목 (또는 25%) | 쏠림 방지 |
| 리밸런싱 | **분기**, 정기보고서 제출 기한 직후 첫 영업일 (4월 초·5월 중순·8월 중순·11월 중순) | 새 재무 반영 시점 (D-05) |
| 교체 버퍼 | 보유 종목은 순위가 상위 `N×1.5` 안이면 유지 | 회전율·거래비용 절감 |
| 비용 가정 | 매매 수수료 + 거래세 (설정값) | 수익률 계산에 반영 |

## 7. 검증 계획

### 7.1 "맞다"의 정의 (사전 고정)
- **1차 지표**: 리밸런싱 시점 포트폴리오의 다음 분기 수익률 vs (a) 유니버스 동일비중 평균, (b) 코스피·코스닥 지수
- **적중률**: 편입 종목 중 다음 분기 **소속 업종 평균 대비** 초과수익을 낸 비율
- **IC (정보계수)**: 종합점수와 다음 3개월 수익률의 순위상관 — 0보다 꾸준히 크면 점수가 의미 있음

### 7.2 실전 추적 (1단계부터)
- 매일 상위 100개 종목의 점수·순위·핵심 지표를 `data/history/YYYY-MM-DD.json`에 저장.
- 리밸런싱일마다 모델 포트폴리오를 기록하고, 이후 성과를 자동 계산해 화면 "성과 추적" 탭에 표시.

### 7.3 백테스트 (3단계)
- 기간: DART 재무 제공 범위(2015~) 내. **2015~2021 개발용, 2022~ 검증용**으로 분리하고 검증 구간은 마지막에 한 번만 본다.
- 시점 정합성: 4.1 규칙 적용.
- 생존자 편향: 상장폐지 종목 포함 (KRX 상장폐지 이력 확보 필요 — 구현 시 소스 확인).
- 보고: 연환산 수익률, 최대낙폭(MDD), 샤프비율, 회전율, 비용 차감 전후 비교.

### 7.4 알려진 한계 (문서화)
- 가치 팩터는 수년간 시장 대비 부진할 수 있다.
- 무료 데이터의 품질 오류 가능성 → 4.6 점검으로 완화.
- 업종 분류의 경계 문제 → 수동 보정표로 완화.
