## ⏳ 열린 질문

### D-07 화면 배포 방식 — 3단계 전에 결정
| 선택안 | 장점 | 확인할 것 |
|---|---|---|
| A. GitHub Pages | 저장소와 일체 | Private 저장소 Pages의 요금제 조건, 접근 통제 가능 여부 |
| B. Vercel | 계정 이미 연결됨, 접근 보호 기능 | 보호 기능의 요금제 조건 |
| C. 로컬 HTML | 비용 0, 완전 비공개 | 자동성 떨어짐 |

### D-08 수집 실행 시각 — 0단계 실측 후 결정
KRX OPEN API의 당일 데이터 제공 시각을 실측한 뒤 정한다.

### D-12 L0~L2 데이터 보관 위치 — 1단계 착수 전 결정
| 선택안 | 장점 | 단점 |
|---|---|---|
| A. GitHub Release 자산 (같은 저장소) | 추가 계정 불필요, 무료 | 파일당 크기 제한, 버전 관리가 수동 |
| B. 별도 데이터 전용 저장소 (Git LFS) | 코드와 분리 | LFS 용량·대역폭 한도 |
| C. 클라우드 객체 저장소 (S3·R2 등) | 확장성 | 계정·비용 관리 필요 |

💡 Claude 추천: **A로 시작**하고, `storage.py` 인터페이스로 감싸 나중에 C로 이전할 수 있게 한다.

### D-14 운용 기준 금액 — 2단계 전에 결정
유동성 한도(주문 금액 ≤ 20일 평균 거래대금의 5%)와 비용 시나리오 계산에 쓸 기준 금액.

| 선택안 | 영향 |
|---|---|
| 소액 (예: 1천만 원) | 유동성 제약 거의 없음 |
| 중액 (예: 1억 원) | 소형주 일부가 제약 받음 |
| 실제 계획 금액 | 가장 현실적 |
