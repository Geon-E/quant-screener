# 협의 방식 — Claude·GPT 공동 의사결정

> 사용자 결정(2026-10-24): "한쪽이 검토하는" 방식이 아니라 **둘 다 의견을 내고 더 합당한 쪽을 채택**한다.

## 왜 이 방식인가
- 1차는 Claude가 설계하고 GPT가 검토했다. 이 구조에서는 GPT가 Claude 추천안을 먼저 보게 되므로 **앵커링(먼저 본 의견에 끌려가는 현상)** 이 생긴다.
- 두 AI가 같은 결론을 냈더라도 서로 독립적으로 낸 결론이 아니면 합의의 의미가 약하다.

## 절차 (회차마다 반복)

| 단계 | 누가 | 무엇을 | 산출물 |
|---|---|---|---|
| 1. 질문 | Claude | 열린 질문을 **추천 없이 중립적으로** 정리 | `reviews/roundN/QUESTIONS.md` |
| 2. 봉인 | Claude | 자기 답변을 GPT보다 **먼저 커밋** (커밋 시각이 증거) | `reviews/roundN/claude_position.md` |
| 3. 독립 답변 | GPT | `claude_position.md`를 **읽지 않고** 질문에 답변 | `reviews/roundN/gpt_position.md` |
| 4. 교차 반론 | GPT → Claude | 상대 답변을 읽고, 의견이 다른 항목에만 반론 | `gpt_rebuttal.md`, `claude_rebuttal.md` |
| 5. 판정 | 아래 기준 | 항목별 채택안 결정, 갈리면 사용자 결정 | `reviews/roundN/RESULT.md` → `DECISIONS.md` |

## 채택 기준 (사전 고정)

1. **근거의 질**: 실측 결과·공식 출처가 있는 주장 > 일반론 > 추측
2. **되돌리기 쉬움**: 틀렸을 때 바꾸기 쉬운 쪽
3. **단순함**: 같은 효과면 구현·운영이 단순한 쪽
4. **비용**: 시간·호출량·금전 비용이 적은 쪽

**판정 규칙**
- 두 답변이 같으면 → 채택
- 다르지만 반론 후 한쪽이 수긍하면 → 수긍한 결론을 채택
- 끝까지 갈리면 → 위 기준 순서로 비교한다. 그래도 우열이 없으면 **선택안을 숫자로 비교한 표를 사용자에게 올려 사용자가 결정**한다.
- Claude는 당사자이므로 단독으로 최종 판정하지 않는다. 판정 근거를 `RESULT.md`에 남기고, 사용자가 이의를 제기할 수 있다.

## 답변 형식 (양쪽 공통)

각 질문마다:
- **선택**: 선택안 기호 또는 대안
- **근거**: 2~5줄
- **반증 조건**: 이 선택이 틀렸다고 판단할 수 있는 관측 결과
- **확신도**: 상 / 중 / 하
